# Анимированная карусель — конвейер

Автор: Марианна Белькова, бизнес-тренер в недвижимости. Карусель — это пост из слайдов,
которые листают. Здесь каждый слайд — ролик на 8–10 секунд: заголовок въезжает по словам,
пункты появляются по очереди, цифры бегут от нуля. Вся анимация — функция времени, поэтому
один и тот же HTML снимается покадрово в MP4 и играет в браузере.

**Папка скилла** — та, где лежит этот SKILL.md (ниже `$SKILL`; в Claude Code это
`${CLAUDE_SKILL_DIR}`). Все команды — через `node "$SKILL/bin/carousel.js" <команда>`.
Справочники рядом: `dsl.md` — как описывать слайды, `rules.md` — правила вёрстки и текста.

## Шаг 0. Проверить окружение

```
node "$SKILL/bin/carousel.js" doctor
```

Проверяет Node ≥ 22, Chrome и ffmpeg; недостающий ffmpeg доставит сам (`npm install` в папке
скилла, один раз). Если что-то отмечено ✗ — остановись и передай пользователю инструкцию из
вывода. Без зелёного doctor дальше не идти.

## Шаг 1. Бриф — пять вопросов

Если ответы уже есть в сообщении, не переспрашивай. Нужно знать:

1. **Тема** и источник (пост, статья, голосовое, «из головы»).
2. **Для кого** — покупатели, продавцы, коллеги, подписчики.
3. **Одна мысль**, которую человек должен унести.
4. **Призыв** в конце: написать в директ, сохранить, прийти на эфир, перейти по ссылке в посте.
5. **Подпись**: имя и строка роли («риелтор · Казань»). Спрашивать только при первом проекте —
   дальше брать из `brand.json`.

Фото человека, скриншоты, планировки — если есть, попроси положить в `assets/photo` (вырезка
на прозрачном фоне, PNG) и `assets/img`. Нет — делаем без фото, это нормально.

## Шаг 2. Проект

```
node "$SKILL/bin/carousel.js" init ./<slug> --name "Имя Фамилия" --role "риелтор · Город"
```

Создаёт папку с `brand.json`, `slides/demo.js` (пример), `caption/`, `assets/`. Второй и
следующие проекты — в новых папках; `brand.json` можно скопировать. Цвета в `brand.json`
менять только по просьбе (палитра по умолчанию — фиолетово-оранжевый закат с жёлтым акцентом).

## Шаг 3. Копидек — ⛔ ГЕЙТ

Перед любым кодом покажи пользователю таблицу слайдов и дождись «ок». Без подтверждения не
собирать и не рендерить. Структура по умолчанию, 6–9 слайдов:

| № | Роль | Что на слайде |
|---|---|---|
| 1 | Хук | Одна фраза-крючок крупно; без рубрики; частицы/фото |
| 2 | Проблема | Что болит у читателя; цифра или сцена |
| 3 | Инсайт | Неочевидная причина; «а на самом деле…» |
| 4…n−1 | Решение | По одному шагу/пункту на слайд, компонент под содержание |
| n | Призыв | OFFER (что сделать) + QUESTION (вопрос для комментариев) |

В таблице для каждого слайда: роль, рубрика (`kick`), заголовок с отмеченным акцентом
(`*слово*`), текст, визуал (компонент), длительность. Плюс подпись к посту по правилам из
`rules.md`. Правки от пользователя вноси в таблицу и показывай ещё раз, пока не будет «ок».

## Шаг 4. Слайды на DSL

Опиши карусель в `slides/<set>.js` по `dsl.md`: `CAR('set', 'Название')`, затем `CS(...)` на
каждый слайд. Один файл — одна карусель; `set` — латиницей, он попадает в имена файлов.
Удали или переименуй `slides/demo.js`, иначе демо отрендерится вместе с твоей каруселью.
Текст поста — в `caption/<set>.txt`.

## Шаг 5. Сборка и проверка вёрстки

```
node "$SKILL/bin/carousel.js" build  --project ./<slug>
node "$SKILL/bin/carousel.js" render --project ./<slug> --set <set> --qa
```

QA печатает по слайду: «вёрстка чистая» или список: *за полями*, *наезд*, *обрезан снизу*,
*вылезает из карточки*, *графика на лице*, *картинка не найдена*. Чини **текстом и
координатами**, не кеглем: сократи фразу, сдвинь `y`, убери пункт. Повторяй до чистого QA.
Ошибка `[js error]` при сборке — синтаксис в slides/*.js: исправь и повтори build.

## Шаг 6. Посмотреть глазами

```
node "$SKILL/bin/carousel.js" render --project ./<slug> --set <set> --stills
node "$SKILL/bin/carousel.js" sheet  --project ./<slug> --set <set>
```

Открой `qa/sheet-<set>.jpg` (инструментом чтения картинок) и сверь с чек-листом в `rules.md`:
одна мысль на слайд, заголовок ≤ 2 строк, ничего на лице, подпись видна, акцент тёплый.
Промежуточные моменты: `--stills --t 1.5,3.2` → `qa/<set>-NN-t1.5.jpg`.
Живой показ: `node "$SKILL/bin/carousel.js" preview --project ./<slug>` → открыть ссылку.

## Шаг 7. Рендер

```
node "$SKILL/bin/carousel.js" render --project ./<slug> --set <set> --slides 1
```

Сначала один слайд — покажи пользователю `out/<set>-01.mp4`. После «ок» — все:
`render --project ./<slug> --set <set>` (≈ 30–60 с на слайд; во время рендера `index.html`
не пересобирать). Форматы: `--story` → 1080×1920, `--wide` → 1920×1080.

## Шаг 8. Упаковка

```
node "$SKILL/bin/carousel.js" pack --project ./<slug> --set <set>
```

Результат — `к публикации/<Название>/01.mp4 … NN.mp4`, `картинки/01.jpg …`, `пост.txt`.
Скажи пользователю путь и как публиковать: в Telegram — альбомом до 10 видео (у роликов есть
тихая звуковая дорожка, иначе Telegram превращает их в GIF); в Instagram — как карусель из
видео или из JPG; ВКонтакте и MAX — картинки.

## Правки

Пользователь говорит «на 3-м слайде …» — правь только этот слайд в `slides/<set>.js`,
затем `build` и `render --slides 3`, затем `pack`. Остальные слайды не трогай и не
перерендеривай.

## Чего не делать

- Не выдумывать цифры, отзывы, регалии, кейсы. Нет данных — писать без цифр или спросить.
- Не класть текст и плашки на лицо на фото (QA это ловит, но смотри и глазами).
- Не рендерить без «ок» по копидеку и без чистого QA.
- Не менять `engine/` ради одного проекта — всё, что нужно, делается в `slides/*.js` и
  `brand.json`; произвольная вёрстка — через `RAW(html, {...})`.
